# Contributing to Fix Life in One Day

Thank you for your interest in improving this practical guide! This project helps people implement Dan Koe's life transformation protocol.

## How You Can Contribute

### 1. Share Your Experience
- Complete the protocol yourself first
- Share what worked and what didn't
- Suggest improvements based on real experience

### 2. Improve Documentation
- Fix typos and clarity issues
- Add helpful examples
- Improve worksheet instructions
- Enhance README sections

### 3. Add Resources
- Link to helpful tools or apps
- Share complementary content
- Add scientific research supporting the methods

### 4. Create Examples
- Provide sample (anonymized) worksheet completions
- Share success stories
- Document common challenges and solutions

### 5. Develop Tools
- Create templates for different note-taking apps
- Build tracking spreadsheets
- Design printable PDFs

## Guidelines

### For All Contributions

1. **Stay True to Core Principles**
   - Identity-first approach
   - Action over theory
   - Honesty and self-awareness
   - Systems over willpower

2. **Be Practical**
   - Focus on actionable advice
   - Provide clear instructions
   - Include specific examples
   - Keep it simple and accessible

3. **Respect Privacy**
   - Never share others' personal worksheet answers
   - Anonymize any examples
   - Keep focus on the method, not personal details

4. **Maintain Quality**
   - Clear, concise writing
   - Proper grammar and formatting
   - Consistent style with existing content
   - Test suggestions before submitting

### For Documentation Changes

1. Fork the repository
2. Create a descriptive branch name
3. Make your changes
4. Test readability and flow
5. Submit a pull request with clear description

### For New Worksheets or Exercises

1. Ensure they align with core protocol
2. Provide clear purpose and instructions
3. Include reflection questions
4. Link to related worksheets
5. Test with real users if possible

### For Examples or Case Studies

1. Remove all personally identifying information
2. Focus on the process, not the person
3. Highlight specific insights or breakthroughs
4. Show before/after thinking patterns
5. Include lessons learned

## What We're Not Looking For

- ❌ Fundamental changes to Dan Koe's core protocol
- ❌ Self-promotion or marketing
- ❌ Unrelated self-help methodologies
- ❌ Overly complex additions
- ❌ Changes that dilute the core message

## Submitting Changes

### Pull Request Process

1. **Before You Start**
   - Check existing issues and PRs
   - Discuss major changes in an issue first
   - Ensure you understand the core protocol

2. **Making Changes**
   - Keep changes focused and atomic
   - Follow existing formatting
   - Update relevant documentation
   - Test all links and references

3. **Pull Request**
   - Descriptive title and description
   - Reference related issues
   - Explain why the change improves the guide
   - Show before/after if relevant

4. **Review Process**
   - Respond to feedback promptly
   - Be open to suggestions
   - Make requested changes
   - Stay patient during review

## Code of Conduct

### Our Standards

- **Respectful**: Treat everyone with respect
- **Constructive**: Focus on improving the guide
- **Honest**: Share genuine experiences and insights
- **Supportive**: Help others on their journey
- **Humble**: Remember we're all learning

### Unacceptable Behavior

- Harassment or discrimination
- Spam or self-promotion
- Sharing others' private information
- Trolling or insulting comments
- Off-topic discussions
